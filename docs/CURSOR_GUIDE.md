# Cursor 사용 가이드

이 문서는 **Cursor** AI 코드 에디터를 처음 쓰거나, 채팅·에이전트·배포까지 실무에서 어떻게 쓰면 좋은지 정리한 가이드입니다.  
Cursor는 **VS Code를 기반**으로 한 IDE이므로, 익스텐션·단축키·폴더 구조는 VS Code와 거의 같습니다.

> 공식 문서: [https://docs.cursor.com](https://docs.cursor.com)  
> 제품·단축키는 버전마다 달라질 수 있습니다. **Cursor → Settings → Keyboard Shortcuts**에서 최종 확인하세요.

## 1. Cursor란?

| 항목 | 설명 |
|------|------|
| 정체 | VS Code 포크 + AI가 **에디터 안에 내장**된 IDE |
| 강점 | 프로젝트 전체 맥락 이해, 여러 파일 동시 수정, 터미널 실행, 자율 작업(Agent) |
| Copilot과 차이 | 확장이 아니라 **IDE 코어**에 AI가 붙어 있음. 코드베이스 인덱싱·에이전트 루프가 기본 |

---

## 2. 설치와 첫 설정

### 설치

1. [cursor.com](https://cursor.com)에서 다운로드
2. Windows / macOS / Linux 설치
3. (선택) VS Code 설정·확장 가져오기: 첫 실행 마법사 또는 **Settings → General → Import from VS Code**

### 처음 해볼 것

1. **프로젝트 폴더 열기** — `File → Open Folder` (예: `isatok` 저장소)
2. **코드베이스 인덱싱 대기** — 우측 하단 등에서 인덱싱이 끝날 때까지 잠시 기다리면 `@codebase` 품질이 좋아짐
3. **모델 선택** — 채팅 패널 상단에서 모델 변경 (속도·품질·요금제에 따라 다름)
4. **Privacy / 데이터** — 팀 정책에 맞게 **Settings → Privacy** 확인

## 3. 화면 구성

```
┌─────────────────────────────────────────────────────────────┐
│  메뉴 / 탭 (열린 파일)                                        │
├──────────┬──────────────────────────────┬───────────────────┤
│          │                              │                   │
│  사이드바  │      코드 편집 영역            │   AI 채팅 패널      │
│  (파일,   │                              │   (Chat / Agent)  │
│   Git,   │                              │                   │
│   검색)   │                              │                   │
│          │                              │                   │
├──────────┴──────────────────────────────┴───────────────────┤
│  터미널 / 문제 / 출력                                          │
└─────────────────────────────────────────────────────────────┘
```

- **왼쪽**: 파일 탐색기, 검색, Git, 확장
- **가운데**: 코드 편집
- **오른쪽 또는 하단**: AI 채팅·에이전트 (레이아웃은 설정에서 변경 가능)
- **하단 터미널**: `npm`, `firebase`, `git` 등 — 에이전트도 여기서 명령 실행 가능

## 4. 핵심 기능 한눈에

| 기능 | 용도 | 대략적인 단축키 (Windows) |
|------|------|---------------------------|
| **Tab** | 다음 코드 줄·블록 자동 제안 | `Tab` 수락 |
| **Inline Edit** | 커서 위치 한 파일 안에서 빠른 수정 | `Ctrl+K` |
| **Chat** | 설명, 질문, 리뷰 (읽기 위주) | `Ctrl+L` |
| **Agent** | 목표를 주면 파일 수정·터미널·탐색까지 수행 | 채팅 패널에서 Agent 모드 |
| **Composer** | 여러 파일에 걸친 변경을 diff로 검토 | `Ctrl+I` |
| **Plan** | 구현 전 설계·트레이드오프 논의 | 모드 전환 (에디터 UI) |

**선택 가이드**

- 한 줄·한 함수만 고치기 → **Ctrl+K**
- “이 함수가 뭐 하는지 설명해줘” → **Chat**
- “버그 고쳐줘 / 기능 추가해줘” (파일 여러 개) → **Agent**
- 큰 변경 전 설계가 필요 → **Plan** 후 Agent

## 5. 채팅(Ask) vs 에이전트(Agent) vs 계획(Plan)

### Ask (채팅 / 질문 모드)

- 코드를 **읽고 설명**하거나, 스니펫을 **제안**함
- 기본적으로 파일을 마음대로 바꾸지 않음 (모드·설정에 따라 다름)
- 적합: 아키텍처 질문, diff 리뷰, “이 에러 왜 나?”

### Agent (에이전트 모드)

- **목표**를 주면 스스로:
  - 관련 파일 검색·읽기
  - 코드 수정
  - 터미널 명령 실행 (`npm test`, `firebase deploy` 등)
  - 필요 시 여러 번 시도
- 적합: 기능 구현, 버그 수정, 리팩터, 배포 준비
- **팁**: 요청을 구체적으로 — “배포해줘”, “카카오 딥링크 스크롤 유지해줘”처럼 **결과**와 **제약**을 적기

### Plan (계획 모드)

- 바로 코드를 많이 쓰기보다 **구현 방안·파일 목록·순서**를 먼저 정리
- 적합: 대규모 리팩터, 탭 구조 변경, 데이터 모델 변경
- Plan으로 합의한 뒤 Agent로 실행하면 되돌리기 횟수가 줄어듦

## 6. @ 로 컨텍스트 지정하기

채팅 입력창에 `@`를 치면 참조 대상을 고를 수 있습니다.

| 참조 | 설명 |
|------|------|
| `@Files` / 파일명 | 특정 파일만 맥락에 포함 |
| `@Folders` | 폴더 단위 (예: `js/app`) |
| `@Codebase` | 저장소 전체 검색·요약 (인덱싱 필요) |
| `@Docs` | 연결된 공식 문서 |
| `@Web` | 웹 검색 (설정·플랜에 따라) |
| `@Git` | 커밋·diff·브랜치 맥락 |

**잘 쓰는 법**

- 범위가 넓을수록 토큰을 많이 씀 → **필요한 파일·폴더만** `@`로 지정
- 예: `@js/app/videosTab.js 레슨 영상 등록에 선수 다중 선택 추가해줘`

## 7. 인라인 편집 (Ctrl+K)

1. 수정할 코드에 커서
2. `Ctrl+K`
3. 자연어로 지시 (예: “null 체크 추가”, “한국어 주석으로 설명”)
4. 제안 diff 확인 후 Accept / Reject

**한 파일·작은 수정**에 가장 빠릅니다.

---

## 8. Tab 자동완성

- 타이핑하면 회색으로 다음 줄이 제안됨
- `Tab` — 수락
- `Esc` — 무시
- 여러 줄·함수 단위 제안도 가능 (프로젝트 스타일을 학습)

**팁**: 프로젝트에 일관된 네이밍·패턴이 있을수록 Tab 품질이 좋아집니다.

---

## 9. 멀티파일 편집 (Composer)

`Ctrl+I`로 Composer를 열고, **여러 파일에 걸친 작업**을 요청합니다.

- 변경은 **파일별 diff**로 표시
- 파일마다 Accept / Reject 가능
- Agent보다 **사람이 diff를 꼼꼼히 볼 때** 유리

예: “`app.html`과 `videosTab.js`에서 레슨 등록 UI를 칩 선택으로 바꿔줘”

## 10. Rules · Skills · Memories

### Rules (규칙)

- **User Rules**: Cursor 설정에 전역 규칙 (예: “한국어로 답변”, “커밋은 요청할 때만”)
- **Project Rules**: `.cursor/rules/` 또는 `AGENTS.md` — **이 저장소 전용** 규칙
- 에이전트가 매 대화마다 참고 → 코딩 스타일·배포 방식·금지 사항 고정

### Skills

- `SKILL.md` 형태의 **재사용 가능한 작업 설명서**
- 예: Firebase 배포, PR 생성, 보안 리뷰
- 에이전트가 상황에 맞으면 스킬 파일을 읽고 절차를 따름

### Memories (메모리)

- 대화에서 “앞으로 이렇게 해줘”라고 하면 **세션·프로젝트에 기억**시킬 수 있음
- 반복 지시를 줄이는 데 유용

## 11. 터미널·배포·Git

에이전트는 **통합 터미널**에서 명령을 실행할 수 있습니다.

| 작업 | 예시 (이사탁) |
|------|----------------|
| 버전 올리기 | `node scripts/prepare-deploy.mjs` |
| Hosting 배포 | `npx firebase-tools deploy --only hosting --project isatok-ef06a` |
| 상태 확인 | `git status`, `git diff` |

**주의**

- `git push --force`, `.env` 커밋 등은 **명시적으로 요청**하기
- 프로덕션 배포·삭제 명령은 에이전트가 확인을 요청할 수 있음 — 의도한 경우 승인

---

## 12. MCP (외부 도구 연동)

**Model Context Protocol**로 DB, GitHub, Linear, Sentry 등을 에이전트에 연결할 수 있습니다.

- 설정: **Cursor Settings → MCP**
- 연결 후 채팅에서 “이 PR의 실패한 CI 요약해줘”처럼 **외부 시스템**을 함께 활용

이사탁 저장소에는 Firebase 관련 스킬(`.agents/skills/firebase-*`)이 있어, 에이전트가 Firestore·Hosting 작업 시 참고할 수 있습니다.

## 13. 추천 워크플로우

### 작은 수정

```
Ctrl+K → 지시 → diff 확인 → 저장
```

### 버그 수정

```
1. Chat: "이 증상 원인 후보 알려줘" + @관련파일
2. Agent: "원인 수정하고 재현 경로 설명해줘"
3. 로컬에서 확인
4. (요청 시) 커밋 / 배포
```

### 기능 추가

```
1. Plan (선택): 범위·데이터 모델·UI 합의
2. Agent: 구현
3. diff 리뷰
4. 배포
```

### 좋은 프롬프트 예시

| 나쁜 예 | 좋은 예 |
|---------|---------|
| “영상 고쳐줘” | “카카오 레슨 링크 클릭 시 영상 탭으로 스크롤했다가 위로 올라가요. 모달 닫아도 위치 유지해줘” |
| “배포” | “방금 수정 hosting만 배포해줘. Functions는 변경 없음” |
| “리팩터” | “`videosTab.js`만 건드리고, 선수 다중 선택은 `memberIds` 배열로 저장” |

## 15. 주의사항·보안

1. **API 키·비밀번호**를 채팅에 붙여 넣지 않기
2. **`.env`**, 서비스 계정 JSON은 커밋·공유 금지 (Rules에도 명시 권장)
3. 에이전트 diff는 **항상 검토** — 특히 `firestore.rules`, 결제, 인증
4. **Privacy 모드** / 팀 정책 확인 (코드가 클라우드로 전송되는 범위)
5. 배포·`git push`는 **본인이 원할 때만** 요청

## 16. 자주 묻는 질문

### VS Code 확장이 그대로 되나요?

대부분 호환됩니다. 일부 VS Code 전용 확장은 안 될 수 있어 공식 호환 목록을 확인하세요.

### 인터넷이 없으면?

Tab·채팅·Agent는 **온라인 모델**이 필요합니다. 오프라인은 일반 편집만 가능합니다.

### 요금은?

[cursor.com/pricing](https://cursor.com/pricing) — 무료 한도 + Pro/Business. 모델·Agent 사용량에 따라 소진 속도가 다릅니다.

### 채팅이 영어로만 나와요

User Rule에 “항상 한국어로 답변”을 추가하거나, 메시지 맨 앞에 “한국어로”를 적으세요.

### 에이전트가 엉뚱한 파일을 많이 고쳐요

- `@파일`로 범위 제한
- “최소 diff만”, “이 파일만 수정” 명시
- Plan으로 범위 합의 후 실행

### 단축키가 안 맞아요

**File → Preferences → Keyboard Shortcuts**에서 `Cursor`, `Composer`, `Chat` 검색 후 재매핑.
